# SwiftUI for Humans MCP server

A remote [MCP](https://modelcontextprotocol.io) server that lets Claude, ChatGPT, and other chat apps and agents without skills search and read the SwiftUI for Humans topics. It's read-only and needs no account: three tools over the same corpus the skills and `website/agents/` are built from.

| Tool | Input | Returns |
|---|---|---|
| `sfh_search` | `query`, `platform?` (`ios` / `macos`), `limit?` (1–25, default 8) | Topic ids with one-line summaries |
| `sfh_get_topic` | `id`, `platform?`, `response_format?` (`concise` default, or `full`) | One topic as Markdown. Concise is at most about 800 tokens and names what it leaves out; full is the whole topic, at most about 1,500 (the check allows up to 5,000) |
| `sfh_review_checklist` | `platform?` | The review checklist plus the top old → new corrections |

Every tool has a `title` and the annotations `readOnlyHint: true`, `destructiveHint: false`, `idempotentHint: true`, and `openWorldHint: false`. An unknown id is a tool error that lists close ids, and a title or alias like `NavigationStack` or `dropdown` resolves to its topic. With `platform`, a page that exists in both editions answers from that edition's page alone, so a Mac question gets Mac code first.

## How it works

- **No build step for the content.** `scripts/agent-build.py` (repo root) renders every view of every topic into `data/corpus.json` (about 2 MB): the full text, the concise text, and per-platform versions. The server only looks things up. `scripts/agent-build.py --check` fails when the file is stale or a view is over budget, like the rest of the agent pack.
- **Stateless Streamable HTTP**, through Vercel's [`mcp-handler`](https://www.npmjs.com/package/mcp-handler) 2.x and the official MCP TypeScript SDK v2 (`@modelcontextprotocol/server`), which is the path [Vercel's MCP docs](https://vercel.com/docs/mcp/deploy-mcp-servers-to-vercel) recommend. It serves the 2026-07-28 spec and falls back to stateless Streamable HTTP for 2025-era clients. No sessions, no Redis, no SSE endpoint.
- **No logging.** The handler runs with `verboseLogs: false`, no `onEvent` hook, and no `console` calls, so requests and tool arguments aren't recorded by this code. Vercel still keeps its standard request logs (time, path, status) for the project, as it does for the website.
- **CORS is open** (`Access-Control-Allow-Origin: *`) because the data is public and browser-based clients need it.

```
api/mcp.ts        the Vercel Function (GET, POST, DELETE, OPTIONS); also served at /mcp
src/server.ts     tool definitions and the request handler
src/corpus.ts     search, id resolution, close-id suggestions, and output formatting
data/corpus.json  generated by scripts/agent-build.py; don't edit
scripts/serve.ts  a local Node server on :3333
scripts/smoke.ts  raw JSON-RPC calls against any endpoint
test/             vitest: corpus and search, and end to end over HTTP
```

## Develop

```sh
cd mcp
npm install
npm test             # unit tests and HTTP tests through the real handler
npm run typecheck
npm run serve        # http://localhost:3333/mcp
npm run smoke        # in another terminal: initialize, tools/list, and tools/call
```

Or by hand:

```sh
curl -s http://localhost:3333/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -H 'MCP-Protocol-Version: 2025-06-18' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"sfh_search","arguments":{"query":"confirm delete"}}}'
```

The MCP Inspector works too: `npx @modelcontextprotocol/inspector`, then connect to `http://localhost:3333/mcp` with the Streamable HTTP transport.

After changing app pages or `agent/src/`, regenerate the corpus from the repo root (`scripts/agent-build.py`) and commit `mcp/data/corpus.json` with everything else.

## Deploy (Vercel)

This folder is its own Vercel project, separate from `website/`, which stays plain HTML with no build step.

1. In Vercel, **Add New → Project**, import `tylerbecks/swiftui-for-humans`, and set **Root Directory** to `mcp`. Framework preset: **Other**. Leave the build and output settings empty; Vercel compiles `api/mcp.ts` itself and `vercel.json` bundles `data/`.
2. Node.js 20 or later (the default is fine). No environment variables are needed.
3. Add a domain, for example `mcp.swiftuiforhumans.com` (a CNAME to Vercel). The endpoint is then `https://mcp.swiftuiforhumans.com/mcp`. The root redirects to the agents page.
4. Optional: under **Settings → Git → Ignored Build Step**, use `git diff --quiet HEAD^ HEAD -- .` so only changes in `mcp/` redeploy it.
5. Check the deployment: `npm run smoke -- https://mcp.swiftuiforhumans.com/mcp`.
6. Add it to Claude as a custom connector (**Settings → Connectors → Add custom connector**, the URL above, no auth) and call each tool from a conversation.
7. Then announce the URL: replace "coming soon" in `agent/src/web/agents.html` with the endpoint and setup steps, add it to the README's "For AI agents" section, and run `scripts/agent-build.py`.

## Connectors Directory submission checklist

Submit through the developer portal at `claude.ai/directory/manage` (sign in with a paid Claude plan, then **Submit new → MCP connector**). Anthropic's [submission guide](https://claude.com/docs/connectors/building/submission) is the source of truth; check it before submitting, since the steps change.

- [ ] Deployed and reachable over HTTPS (step 1 asks for the `https://…/mcp` URL)
- [ ] Every tool has a `title` and `readOnlyHint` (done; the tests check it). The portal's **Tools** step flags any that don't
- [ ] Authentication: **none**. The data is public, so there's no OAuth and no reviewer test account to provide; say so in **Test & launch**
- [ ] Tested as a custom connector in Claude, every tool called at least once (the portal asks you to confirm)
- [ ] **Listing:** name (`SwiftUI for Humans`, up to 100 characters), a one-liner (up to 200), a description (up to 2,000), one to five categories, and a permanent URL slug
- [ ] **Documentation URL:** `https://www.swiftuiforhumans.com/agents`, once it describes the server (see step 7 above)
- [ ] **Privacy policy URL:** `https://www.swiftuiforhumans.com/privacy`. The server collects and logs nothing beyond Vercel's standard request logs, which the policy's "This website" section covers. Consider adding a sentence that names the MCP server explicitly before submitting
- [ ] **Support contact:** `https://www.swiftuiforhumans.com/support` or `tylerdbecks@gmail.com`
- [ ] **Icon:** `website/images/icon.png` (512 × 512 PNG)
- [ ] **Use cases:** reads data only; no account or setup needed
- [ ] **Data handling:** your own content, not a third-party API; no health data or sponsored content
- [ ] **Compliance:** the seven policy acknowledgments, including the Anthropic Software Directory Terms and Policy
- [ ] Not affiliated with Apple: keep that in the description, as on the website

Escalations go to `mcp-review@anthropic.com`.
